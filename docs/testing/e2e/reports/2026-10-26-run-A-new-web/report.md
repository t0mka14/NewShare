Notes: `formatDate.js` calls `new Date(value)` on a zoneless string. Evidence: F-A-1-relative-time-offset.png. **Status:** fixed in the web repo (2026-10-29), not yet deployed or re-run. Cause: the protocol and library endpoints sent raw zoneless DB datetimes (`dateStrings`), and `formatDate.js` read them as browser-local time. Fix (web repo `task_protocoller_web_app` commit `44d8490`): `toIso` moved to `backend/src/utils/dateIso.js` and used for `created_at`/`updated_at` in `protocolController` (list, by id) and `libraryController` (list, entry); `formatDate.toDate` reads a zoneless string as UTC. Recordings "Received" already went through `toIso`. Tests: `protocolController.test.js`/`libraryController.test.js` "sends ... as ISO-8601 UTC (F-067)", `formatDate.test.js` (TZ Europe/Prague: "saved 2 minutes ago as 2 minutes ago"), all red before the fix.
