## How to work (what worked)

**Fix rounds:**
- Agents: `domain-engineer`, `audio-engineer` and `ui-engineer` for the app, or `general-purpose` for the web. Use `model: sonnet`, and give a self-contained brief: finding, code pointers, decided design, acceptance criteria, and "show the new test failing before the fix".
- Review every diff.
- Check that the new tests fail on the old code yourself: copy the old main file back from `git show HEAD:<path>`, run only that test, then restore the new file.
- Count the test results from `app/build/test-results/test/*.xml`, because the Gradle exit code alone can mislead. In one case a locked `output.bin` from an agent's background Gradle run made the build fail while the XMLs were stale.

**E2E runners:**
- The runner's Write tool refuses `report.md`, so it returns the text and the orchestrator saves it.
- Steps that need the user (an elevated shell) use marker files `WAITING-FOR-*` in the run folder. Watch for them with Monitor, and **re-arm it before the 30-minute expiry**: run 12 missed a second request that way.
- Delete the marker once the user says "done".

**Real microphone loss on this VM:**
- Disabling the `CABLE Output` endpoint does nothing to an open line (F-131).
- The VB-Audio driver can't be disabled while it's in use.
- What works: the user runs `Stop-Service -Name Audiosrv -Force; Start-Sleep 15; Start-Service -Name Audiosrv` in an elevated shell. Ask them to keep the app and launcher windows open.

**Typing under RDP doesn't reach the app** (F-116). Set the clinic token with `scripts/run-07/set_token.py` while the app is stopped. `type_text` worked for questionnaire fields in run 12.

**Bookkeeping helpers:** `scripts/orchestrator/` holds the link check, the findings count and the leak scan (see its README). Run the leak scan before every commit. Write tokens as `<token:E2E 1026 Clinic A>` and installation IDs as `<installationId>`. Copied `examination.json` files contain the installation ID, so redact them.

**Commits:**
- one for code, one for docs;
- end each message with the attribution line;
- never commit `app/data*` or `app/fake-sessions-root/`. The latter is an empty folder left by a test, untracked and harmless.
