## Open gaps from the third review of `redactPaths`

Logs don't leave the computer, so nothing is exposed today, and no current code was found to produce any of these. Findings are from a Java port plus reading the code, not from running the Kotlin.

1. **Rated major by the reviewer:** `redacted()` checks only the throwable's own type. `RuntimeException(jsonDecodingException)` copies `cause.toString()` into its message, so the JSON survives in the wrapper. Fix: drop a wrapper's message when anything in its cause chain is a `SerializationException`.
2. `PLACEHOLDER_FRAGMENT` (`<+(<...)`) is quadratic on long runs of `<`: 20,000 takes about 4 s, 50,000 about 45 s. Suggested, untested: a `(?<!<)` guard at the start.
3. A bare session file name followed by something outside the trailing set survives: `clip_ABC123.wav:1234`, `` `clip_ABC123.wav` ``, curly quotes.
4. Extensionless names that embed the code survive, e.g. `ABC123_s1`, and rendered clip stems. The function can't recognise them; list as a limit in the KDoc.
5. Middle fragments of a spaced path survive, e.g. `Marie` in `C:\Users\Jan Marie Novak\...`. The KDoc names only the final fragment.
6. Prefixed folder names survive (`tmp_2026-07-01_ABC123_s1`). No code builds one.
7. `out#0/ABC123` is exempt as an ffmpeg tag. It would need a folder name containing `#`.
8. Small mismatches: `C:\x>` gives `<path>>`, and `2026-07-01_10-15-30` gives `<session>`.
9. Not about redaction: `lastDiagnosticLine` can return a non-error line such as `Exiting normally`, hiding an earlier real error.

Not traced: non-path participant data in messages, e.g. `NumberFormatException: For input string: "ABC123"`.
